# 三级结构优先的情报归类

分类唯一源是 [`knowledge/technology-navigation.json`](../knowledge/technology-navigation.json)。[`三级结构清单`](../indexes/technology-navigation.md)供编辑阅读，[JSON索引](../indexes/technology-navigation.json)供程序匹配；两份索引和网站都由唯一源生成，不能分别手改。

## 先匹配现有清单

1. 阅读最新索引，确认情报的主要研究对象和实际交付结果，再选择“技术领域 → 技术路线 → 核心技术”。不要只凭产品名称、模型架构、宣传关键词或“Agent”“Virtual”字样归类。
2. 逐项对照核心类的 `research_object`（对象）、`primary_output`（主要产出）、`discriminator`（最具辨识特点）及 `boundary`（与相近类的边界）。对象与产出相符、关键特点不冲突时，优先复用原类。
3. 已有技术通过成员 `technology_id` 找到唯一主分类；新技术加入合适核心类的 `members`，注明模型、平台、评测方法等角色。同一技术只设一个主分类，跨领域联系使用现有技术关联，避免在多个分支重复挂载。
4. 日报的主要分类跟随直接支持该事件的关联技术；从该技术复用现有六层 `technology_path` 写入归档，以兼容历史标准。三层分类用于选类与浏览，六层路径是当前归档格式，不能用无关旧模型的路径凑校验。

## 差异明显时，先改清单

当研究对象、主要产出或关键评价方式与现有类明显不同，先暂停归类，不强行塞入最相近名称。

1. 先在唯一源中增加或修订最小必要的核心类；只有确实缺少上位路线或领域时才增加上层。保持稳定 ID，不复用旧 ID 表示无关含义。
2. 填写对象、主要产出、**最具辨识特点**和边界。特点应能回答“和最接近的已有分支相比，哪一个可核对的差异足以决定归属”，不能只写“更先进”“更智能”或换一个名称。
3. 在开发日志及 PR 中记录最接近的原类、不能复用的原因、索引变更和判别依据。分类说明是编辑框架；关于新技术的事实仍须由一手来源支持。
4. 先运行 `pnpm generate` 更新三级索引并检查差异。新核心类可以暂时没有成员，明确表示尚未收录；不要复制别类技术来填空。
5. 再补充技术知识及其成员归属，归类新情报。重新生成索引，运行检查、测试与构建；通过后将清单变更、情报档案和索引放在同一 PR 审阅。

## 目前最易混淆的边界

- scGPT的主要归属是单细胞表示学习。若新进展主要交付干预后的细胞响应，应先评估细胞与系统建模下的新类，不能仅因输入都是单细胞数据而混为一类。
- insitro Virtual Human当前条目交付靶点假设，归于靶点发现；名称中的Virtual Human不能替代任务判断。
- AlphaFold 3产出复合物结构预测；OpenBind提供隐藏实验参照的盲测框架。两者属于同一路线的不同核心类与角色。
- RFdiffusion此处按蛋白骨架生成归类。小分子生成、抗体序列优化或实验选点如果缺少相符核心类，应先扩展索引，不能只按相同网络架构归入。

机器检查会拒绝重复节点、缺失判别字段、未知技术、技术重复归类或漏归类、以及未重新生成的索引。语义是否足以区分类别仍由来源核验与编辑审阅判断。
