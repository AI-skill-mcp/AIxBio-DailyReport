# 每日采编与自动归档

继续使用原“AI × Bio 每日简报”定时任务，不增加 GitHub Actions 采编定时器。原任务负责检索、实际阅读来源和编辑判断，仓库脚本负责格式与引用检查，Pages 工作流负责部署。任务保存的指令见 [采编提示词](../prompts/daily-report.md)。

## 执行环境

原任务必须具备联网检索、读取及修改本仓库、运行 Node.js 24/pnpm、推送开发分支和创建/合并 PR 的权限。当前交互会话能通过本机 SSH 推送，不代表云端定时任务会继承相同权限；只有在原任务执行环境中试跑成功，才能确认无人值守链路已接通。不能依赖每次运行时人工登录 GitHub 网页，也不将凭据写进提示词或仓库。

在任务编辑页保留原任务 ID、名称、时间、时区和通知偏好，更新采编指令及其执行项目。若原环境无法访问仓库，停止在该环节并报告缺少的权限或执行能力，不创建第二个同名任务，也不宣称已归档。

## 单次执行

1. 从最新 `main` 建立或复用 `codex/daily-YYYY-MM-DD`；复用同一天的 PR。保留工作区内其他内容，不强制覆盖分支。
   先检查远程 `main`：当天已有已发布日报时，仅核对现有档案、部署、正式页面及下载链接；没有明确修订请求就返回“同日报已存在，幂等无变化”，不创建新分支、空提交、PR或无变化部署。2026-10-16原任务试跑应走此路径；未实际写入时不能据此宣称推送与合并能力已验证。
2. 按上海日期搜索最近 24 小时新闻，不足时扩展至 72 小时并在摘要写明。打开论文、作者、机构或项目的一手原文，核对事件日、在线发布日、方法、结果与限制。每条 `sources[0]` 放直接支持本次事件的主来源，背景资料放在后面。已报道事件、只有转载或日期不清楚的内容不发布。
3. 先按最新[三级结构清单](../indexes/technology-navigation.md)归类，对照研究对象、主要产出、最具辨识特点和边界。差异明显时，先更新 `knowledge/technology-navigation.json` 并生成索引、说明与相邻类的关键区别，再补充技术与情报归属；遵循[完整归类流程](classification.md)，不重复挂树。在仓库外保存候选 JSON，补充有来源支持的技术与兼容的六层归档路径。先完成整期核验，再标为 `published`。没有合格进展则保留线上版本，不发布空日报。
4. 使用现有依赖与生成器：

```sh
export ASTRO_TELEMETRY_DISABLED=1
pnpm install --frozen-lockfile
pnpm import:report /absolute/path/to/candidate.json
pnpm generate
pnpm check
pnpm test
pnpm build
```

5. 审阅事实表述、生成 Markdown、索引和差异后，提交本期 JSON/Markdown、必要知识及浏览分组变更和索引。创建或复用同一 PR，核对最新 head 的远程检查；全部通过后合并。每期保留来源核验说明，编辑推断明确标注。
6. 确认合并进入远程 `main`，对应 Pages 部署成功，正式网站的日报详情、JSON/Markdown 下载和搜索均含本期内容，才报告发布成功。记录报告日期、文章数、PR、提交、部署与正式链接。

## 幂等、修订与失败

- 相同日期、相同 JSON 内容重复导入为 `unchanged`；对象键顺序及缩进变化不会生成新档案。
- 相同日期内容不同即报冲突，不自动覆盖。明确修订需在 PR 中编辑事实源并说明原因，再生成和验证。
- 已发布文章按首条主来源的规范化 URL 与事件日检查重复；移除跟踪参数与片段，保留有意义的查询参数。共享背景资料不会将两个独立事件误判为重复。不同链接指向同一论文的情况仍需编辑核对 DOI、标题与版本。新版本只有在事件和更新内容有证据时才能另报。
- 导入前校验整个候选仓库；失败不写日报、Markdown 或索引。后续校验、构建或 CI 失败时保留开发分支，禁止合并。网络重试前先读远程状态，避免重复提交或重复 PR。
- 导入使用仓库级排他锁，禁止两个运行基于旧快照同时写入。遇到占用立即停止；如前一次进程异常退出留下锁，先确认没有导入进程运行、检查工作区与档案，再明确移除遗留锁。不能自动抢锁或删除其他运行的锁。
- 受限本机环境使用上述进程环境变量关闭 Astro 遥测，避免首次运行尝试写入工作区外的用户偏好目录；不需要修改全局设置。
- 推送成功、CI 成功和网站发布成功是三个状态；失败报告写清停止在哪一步，禁止将部分完成描述为全链路成功。

## 采用的社区方案

保留 GitHub 分支/PR 和 [Astro 官方 Pages 发布方式](https://docs.astro.build/en/guides/deploy/github/)，复用已有 Ajv 校验与确定性生成器。评估过 [create-pull-request](https://github.com/peter-evans/create-pull-request)：它适合在 Actions 工作区产生变更后开 PR，但不能接收原 ChatGPT 任务的结果，也不能替代来源核验；使用默认令牌还会影响后续工作流触发，因此本次不新增该依赖或第二个采编定时器。
